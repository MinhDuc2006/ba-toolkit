# User stories

## Purpose
Express the functional requirements from the user's point of view, ready for an agile backlog.

## Inputs
Functional and stakeholder requirements above; context.md › Stakeholders.

## How to write
- "As a <role>, I want <capability>, so that <benefit>."
- Roles come from context.md stakeholders — never "As a user".
- Group stories into epics (one per feature area).
- Check each against INVEST: Independent, Negotiable, Valuable, Estimable, Small, Testable. Split stories that fail Small or Testable.

## Format
### Epic: <name>
| ID | User story | Traces to | Priority | Notes |
|---|---|---|---|---|
| US-01 | As a …, I want …, so that … | FR-01 | Must | |

## Quality checks
- Every Must/Should FR is covered by at least one story.
- The "so that" states a real benefit, not a restatement of the want.

## Technique note
User stories are a conversation starter, not a full spec. INVEST is the checklist BAs use to tell whether a story is ready for a team to estimate.
