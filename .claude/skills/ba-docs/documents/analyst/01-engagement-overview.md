# Engagement overview (start here)

## Purpose
The entry point for any BA picking up this engagement: what it is, what's been done, where everything is, and what's left.

## Inputs
context.md; list of all files in outputs/ and inputs/.

## Structure
1. **One-paragraph summary**: organisation, scope, goals, current status.
2. **Deliverables map**: table of every output file — what it contains, date, status (draft/reviewed/approved), key IDs inside.
3. **Analysis flow**: Mermaid flowchart showing how outputs feed each other (intake → system map → process → gap → requirements → docs) with the actual files present.
4. **Key findings in 5 bullets** with IDs.
5. **Status and next steps**: what's done, in progress, not started; who to talk to next.
6. **How to continue**: which `/ba-*` skill to run next and why.

## Format
| File | Contents | Date | Status | Key IDs |
|---|---|---|---|---|
| outputs/01-system-map.md | Current system map, health ratings | | Draft | C-01…C-12, H-01…H-08 |

## Quality checks
- Every file in outputs/ is listed.
- A new BA could find any finding's source within two clicks.

## Technique note
A handover/overview doc is the BA's equivalent of a README — it saves the next person days of reverse-engineering.
