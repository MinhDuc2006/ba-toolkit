# Business case

## Purpose
Justify the investment by comparing options on cost, benefit and risk.

## Inputs
03-gap recommendations & roadmap; 02-process metrics (time saved); context.md › Constraints, Data and metrics; cost figures from the user.

## Structure
1. **Background and objective** (3 lines, linked to company goals).
2. **Options** — at least: Option 0 *Do nothing*, Option 1 *Quick wins only*, Option 2 *Full recommendation*. One line describing each.
3. **Costs per option** — one-off and ongoing; staff time, tools, training, disruption. Show formula: e.g. `hours × rate`.
4. **Benefits per option** — time saved (hours × rate), errors avoided, revenue protected/gained, risk reduced. Separate cash benefits from non-cash.
5. **Comparison table** — cost, benefit, net benefit (year 1 and year 3 if possible), payback period, key risk.
6. **Risks and mitigations** — top 3–5.
7. **Recommendation** — which option and why.
8. **Assumptions** — every figure's basis, labelled estimate/confirmed.

## Format
| | Do nothing | Quick wins | Full |
|---|---|---|---|
| One-off cost | 0 | | |
| Annual cost | | | |
| Annual benefit | | | |
| Payback | — | | |
| Key risk | | | |

## Quality checks
- No invented money figures: every figure comes from the user, inputs, or a shown calculation with stated assumptions; otherwise `TBD`.
- "Do nothing" has a real cost (ongoing waste, risk), not zero impact.

## Technique note
(Analyst reference only.) Including a do-nothing baseline and a low-cost option is standard practice and makes the recommended option's value visible.
