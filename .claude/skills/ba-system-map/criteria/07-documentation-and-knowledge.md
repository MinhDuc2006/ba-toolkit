# Documentation and knowledge

## Looks at
Whether how the part works is written down and understood by more than one person.

## Signs it is too loose
- Knowledge held by one or two people; documentation exists but is out of date.

## Signs it can be improved
- Documented, but hard to find or follow; training is informal.

## Signs it needs more work
- Nobody fully understands it (e.g. legacy logic, custom macros).

## Questions to ask
- If the main person was away for a month, what would break?
- Where is this written down, and when was it last updated?
