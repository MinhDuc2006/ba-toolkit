# Focus areas

## Purpose
Turn the ratings into three clear lists the user asked for: what's too loose, what can be improved, what needs more work.

## How to write
- Three sub-sections in this order: 🟠 Too loose, 🟡 Can be improved, 🔴 Needs more work.
- For each item: ID, part, the problem in business terms (time, cost, risk, customer impact), and a suggested direction (not a product).
- In 🔴, tag each item: **Fix**, **Replace**, **Build**, or **Investigate**.
- Order each list by impact (highest first). Mark quick wins (low effort, clear benefit) with ⚡.
- End with a 🟢 Solid list — things to protect during change.

## Format
### 🟠 Too loose
1. **C-01 Order spreadsheet** — no validation, re-keyed daily → errors in stock orders (~30 min/day). *Direction:* single source for order data; remove manual re-keying. ⚡

### 🟡 Can be improved
### 🔴 Needs more work
1. **C-05 Rostering** — [Investigate] no one could explain how shifts are assigned.

### 🟢 Solid — protect

## Technique note
These lists feed directly into /ba-gap (why is it loose?) and /ba-requirements (what must the target state do?). Tag items by IDs so they stay traceable.
