# Root cause — 5 Whys

## Purpose
Dig beneath each priority problem to a cause the organisation can act on.

## How to write
- One block per agreed priority problem.
- Ask "Why?" repeatedly (usually 3–5 times). Each answer must be supported by evidence or marked `[Assumption]` / "to verify with <who>".
- Stop when you reach something the organisation controls and could change (a rule, design, resource, or incentive). If two causes appear at a level, branch.
- Name the root cause `RC-xx` and its dimension.

## Format
#### Problem 1: <symptom in business terms> (links: G-01, P-02)
1. Why? …
2. Why? …
3. Why? …
4. Why? …
5. Why? …
**Root cause RC-01** (<dimension>): … · Confidence: High / Medium / Low · Verify with: …

## Technique note
5 Whys, from Toyota, is simple but easy to misuse: stop at "human error" and you've found a symptom, not a cause. Ask why the system allowed the error.
